## プレーンテキストではなくMarkdownを使う理由

プレーンテキストでは構造が失われます。見出しはほかの行と見分けがつかず、リストはばらばらの文になり、表は順番の崩れた単語の寄せ集めになってしまいます。Markdownは普通の文字を使って構造を保つので、ほぼどこに貼り付けても構造が崩れません。

同じ出力を、Markdownで保存するメモアプリ、ドキュメントサイト、Wiki、READMEファイル、AIアシスタントとのチャットでそのまま使えます。生のテキストのままでも読みやすく、手で編集するのも簡単で、バージョン管理でも変更点がはっきりわかります。

## ページの各部分はどう書き出されるか

内容の種類ごとに、それぞれのMarkdown表記があります。

| 画像の中 | Markdownでの表記 |
| --- | --- |
| 見出し | 1つ以上の`#`で始まる行 |
| 箇条書き | `- `で始まる行 |
| 番号付きリスト | `1.`、`2.`のように始まる行 |
| 表（表モードで読み取り） | 列の間をパイプで区切ったMarkdownの表 |
| コード（コードモードで読み取り） | コードブロック（フェンス） |

短いチェックリストのスクリーンショットをドキュメントモードで読み取ると、たとえば次のようになります。

```markdown
# リリース前チェックリスト

新しいバージョンにタグを付ける前に実行します。

- mainブランチを凍結する
- 変更履歴を更新する

1. パッケージをビルドする
2. すべてのテストを実行する
```

段落内で折り返された行はつなげられ、行末のハイフンで分割された英単語も元どおりになるので、段落は何行にも分かれず、Markdownの1行になります。

## 文章、表、コードが混在するページ

画像は一度に1つのモードで読み取られ、モードは画像ごとに個別に選びます。段落と表が並んだスクリーンショットや、途中にコード例があるチュートリアルのページでは、この点が重要です。ドキュメントモードは文章向けなので、表をそのモードで読み取ると、たいていグリッドではなく文字の行として出てきます。

対処法はページを分けることです。文章部分と、表やコードの部分で別々にスクリーンショットを撮り、それぞれを適切なモードに設定して、ドラッグで順番に並べます。「ドキュメント全体」表示で全ページを1つのMarkdownファイルにまとめるか、ページごとのファイルを入れたZIPとして書き出せます。

表の多い画像については、[画像から表を抽出する方法](/ja/guides/how-to-extract-tables-from-images)で行と列を正しく取り込む方法を紹介しています。コード例については、[コードのスクショをテキストに変換](/ja/code-screenshot-to-text)で、括弧や形の似た文字など確認すべきポイントを説明しています。

## AIへのプロンプトでMarkdownを使う

AIアシスタントとのチャットに画像ではなくテキストを貼り付ければ、相手に何を見せるかを自分で管理できます。先にテキストを読んで読み間違いを直し、プライベートな部分や関係のない部分を削り、見出し、リスト、表をはっきり示したまま渡せます。

Markdownで貼り付けた表は行と列がテキストとして保たれるので、「3月の列と4月の列を比べて」のように、質問の中で直接参照できます。番号付きリストは番号が保たれるので、「手順3を書き直して」が、あなたとアシスタントにとって同じ意味になります。

## 貼り付ける前に出力を整える

いくつか簡単に確認するだけで、Markdownがきれいになります。

- **見出しのレベル。** ページのタイトルや各セクションの見出しが、意図したレベルになっているか確認しましょう。`#`の追加や削除はすぐにできます。
- **複数のスクショにまたがる番号付きリスト。** スクリーンショットをまたいで続くリストは、1から振り直されることがあります。ページを結合した後に番号を確認してください。
- **残したい改行。** 詩、住所、歌詞などは、行の結合をオフにして、各行をそのまま残しましょう。
- **繰り返される間違い。** 同じ単語が毎回同じように読み間違えられている場合は、検索と置換で一度に直せます。

ワープロソフトで仕上げたい場合は、[画像をWordに変換](/ja/image-to-word)で、同じ見出しとリストを持つ.docxを作れます。
